# ЛР 2. Метрики сервісу і межа масштабованості (варіант 26)

Сервіс `/telemed-sessions` з ЛР 1, доповнений метриками Prometheus, коректною зупинкою і сервером Prometheus у стенді.

## Параметри варіанта 26

| Параметр | Значення |
|---|---|
| Ліміти контейнера web (з ЛР 1) | 1 CPU, 512 МБ |
| `DB_POOL_SIZE` | 10 |
| Бакети гістограми | Г2: 2, 5, 10, 20, 50, 100, 200, 500, 1000, 2000 мс |
| Додаткова метрика | М4: частка запитів з тривалістю обробки ≤ порогу, за лічильником бакета |

## Первинний проєкт (зафіксовано до коду)

**Метрики сервісу** (реєструються один раз під час імпорту модуля, оновлюються в одному ASGI-проміжному обробнику):

| Метрика | Тип | Мітки | Що рахує |
|---|---|---|---|
| `http_requests_total` | counter | `method`, `path` (шаблон маршруту, напр. `/telemed-sessions/{session_id}`), `code` | завершені запити |
| `http_request_duration_seconds` | histogram, межі Г2 у секундах (`0.002` … `2.0`) | `method`, `path` | тривалість обробки в сервісі |
| `http_requests_in_progress` | gauge | — | запити в обробці зараз |
| `process_cpu_seconds_total` | counter (стандартний колектор `prometheus_client`) | — | CPU процесу сервісу |

Шлях без маршруту (404 на невідомий URL) іде з міткою `path="unmatched"`, щоб довільні URL не створювали нових рядів.

**Нові ендпоінти і змінні:** `GET /metrics`, `GET /livez` (200 без бази), заголовок `X-Pod` = `POD_NAME` або hostname, пул asyncpg `max_size = DB_POOL_SIZE`.

**Коректна зупинка:** uvicorn у exec-формі `CMD` отримує SIGTERM як PID 1, перестає приймати зʼєднання, дочікується запитів в обробці (`--timeout-graceful-shutdown 8` < `stop_grace_period` 10 с), lifespan закриває пул, код виходу 0. nginx: `proxy_next_upstream error timeout` і короткий `proxy_connect_timeout`, щоб запит на зупинений екземпляр повторювався на іншому.

**Prometheus:** `scrape_interval: 5s`, `dns_sd_configs` за іменем `web`, `type: A`, порт 8000, `refresh_interval: 5s`; том `promdata`; порт 9090 на хост; мережа `frontend` (там само, де web і lb).

**Генератор:** Go, відкритий контур, горутина на запит (кількість одночасних запитів не обмежена пулом, тому фактична інтенсивність надсилання дорівнює заданій), тайм-аут 5 с. Профіль: прогрів 10 с на 200/с, сходинки по 20 с від 200 з кроком 200. Посекундний CSV: задана, надіслано, досягнута (2xx, завершені в цю секунду), 2xx, не-2xx, помилки зʼєднання, p50/p95/p99. Підсумок по сходинках (останні 15 с кожної) — JSON. Зупинка: дві сходинки поспіль < 0.9 заданої або сходинка з заданою ≥ G.

## Запуск

```bash
cd lab2
cp .env.example .env
docker compose up -d --build          # db, web, lb, prometheus
docker compose up -d --scale web=4 && docker compose restart lb
./scripts/series.sh                   # усі прогони кроків 3, 6, 7
```
